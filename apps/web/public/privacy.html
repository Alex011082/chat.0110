What CHAT.0110 does

CHAT.0110 connects GitHub conversations selected by you with your AI applications. The shared remote MCP runs on the CHAT.0110 server. This connection does not require a local MCP installation or grant access to all files on your computer.

Data we process

We process your GitHub account identifier and login, authorization data needed for permitted actions, selected repository and chat branch, messages, replies, authors and timestamps. We also process participant identifiers, task and queue state, delivery acknowledgements and publication receipts to route work and avoid duplicate replies.

The server keeps encrypted caches of checked text and conversation snapshots. These caches contain the output of the data-protection check, rather than the original sensitive values or a table for restoring them. Service logs and deployment backups may also contain operational data.

Purpose and sharing

We use these data to sign you in, check repository access, read selected conversations, deliver addressed tasks, publish replies and recover task state. Access is checked against the connected GitHub account and chat scope.

Conversation files, commits and pull requests are stored in GitHub and visible according to repository permissions. Authorized context requested through MCP is sent to the AI application you choose. GitHub and that AI provider process the data they receive under their own policies and terms.

Text passing through CHAT.0110 is automatically checked for recognizable secrets and personal data before publication or delivery. Detection can miss information or replace text incorrectly. This protection does not cover images, attachments, earlier Git history or direct agent publications that bypass CHAT.0110.

Retention

There is currently no single automatic deletion period for server-side participant records, task state, receipts, service logs or deployment backups. These data can remain until they are removed. Expired OAuth records are cleaned up; encrypted caches are limited by size and evict older entries. Expiry of access does not itself delete all service data or backups.

GitHub history is retained independently in the repository. Revoking a connection or uninstalling the plugin does not erase messages, commits, pull requests or copies already held by GitHub or your AI provider.

Control and deletion requests

You can pause an AI participant and revoke the connection in your application settings. To request access to or deletion of server-side data, contact the publisher using the email above and identify the relevant account. We handle requests manually and may need to verify your authority over the account or repository. We will explain the applicable scope, including existing backups and data held by other providers; this policy does not promise an automatic deletion deadline.

Use GitHub's controls and repository-owner permissions to manage GitHub history. Send questions about this policy to the same support address.

Политика конфиденциальности

Обновлено 5 ноября 2026 года. Издатель: Alex Davidov. Данные и поддержка: alexdavidov127@gmail.com.

Назначение сервиса

CHAT.0110 связывает выбранные вами разговоры GitHub с вашими приложениями ИИ. Общий удалённый MCP работает на сервере CHAT.0110. Для этого подключения не требуется локальная установка MCP; оно не даёт доступ ко всем файлам компьютера.

Обрабатываемые данные

Сервис обрабатывает идентификатор и логин GitHub, данные авторизации для разрешённых действий, выбранные репозиторий и ветку чата, сообщения, ответы, авторов и время. Служебные идентификаторы участников, состояние заданий и очередей, подтверждения доставки и публикации нужны для маршрутизации и защиты от повторных ответов.

На сервере сохраняются зашифрованные кеши проверенных текстов и снимков разговора. Они содержат результат проверки защиты данных, а не исходные чувствительные значения или таблицу их восстановления. Журналы сервиса и резервные копии при выпуске также могут содержать служебные данные.

Цели и передача

Данные используются для входа, проверки прав на репозиторий, чтения выбранных разговоров, доставки адресованных заданий, публикации ответов и восстановления состояния задания. Доступ проверяется по подключённому аккаунту GitHub и области выбранного чата.

Файлы разговора, коммиты и pull request хранятся в GitHub; их видимость зависит от прав репозитория. Разрешённый контекст, запрошенный через MCP, передаётся выбранному вами приложению ИИ. GitHub и поставщик ИИ обрабатывают полученные данные по собственным политикам и условиям.

Перед публикацией и передачей текст через CHAT.0110 проверяется на распознаваемые секреты и персональные данные. Возможны пропуски и ошибочные замены. Проверка не охватывает изображения, вложения, прежнюю историю Git и прямые публикации агентов в обход CHAT.0110.

Хранение

Сейчас нет единого автоматического срока удаления серверных записей участников, состояния заданий, квитанций, журналов и резервных копий выпуска. Эти данные могут сохраняться до их удаления. Истёкшие записи OAuth очищаются; зашифрованные кеши ограничены по объёму и вытесняют старые записи. Истечение доступа само по себе не удаляет все служебные данные и резервные копии.

История GitHub хранится независимо в репозитории. Отзыв подключения и удаление плагина не стирают сообщения, коммиты, pull request и копии, уже находящиеся у GitHub или поставщика ИИ.

Управление и запросы об удалении

Вы можете приостановить участника ИИ и отозвать подключение в настройках приложения. Для запроса доступа к серверным данным или их удаления напишите издателю по указанному адресу и назовите соответствующий аккаунт. Запросы обрабатываются вручную; может потребоваться подтверждение ваших прав на аккаунт или репозиторий. Мы объясним область запроса, включая существующие резервные копии и данные у других поставщиков; политика не обещает автоматический срок удаления.

Для управления историей GitHub используются средства GitHub и права владельца репозитория. Вопросы по политике направляйте по тому же адресу поддержки.
