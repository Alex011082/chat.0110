# Пакет выпуска CHAT-004

Статус: кандидат в draft PR13. **Выпуск не разрешён и не выполнялся.** Ограниченный
живой Codex → Claude → итог [B2 прошёл](codex-host-pilot.md). Постоянный host после
restart и полная эксплуатационная приёмка не пройдены. Владелец отдельно выбрал
только доставку по событию: модельные heartbeat-проверки раз в пять минут и
мастерский relay не включаются.

## Проверяемая версия и условия допуска

Точный итоговый head и CI записаны новым сообщением в PR12; брать проверенный head
PR13, а не произвольный HEAD рабочей папки. Base — ветка PR11. В main пока нет всего
MCP-среза; порядок интеграции PR11/13 требует отдельного решения. Активный сервер
ранее read-only проверен на релизе 4ee2daf216e2, это надо повторить перед выпуском.

Оба настоящих Desktop wake и разрешённый helper Claude подтверждены в B2. Реальный
HTTP-маршрут веб-чата → первый ответ → второй → итог дал ровно три tasks done.
До решения о выпуске нужны постоянный host/его restart, reconnect/revoke/stop/expiry,
физический ввод в UI и свежий Git-файл в UI без reload. Fixture runner и чистый
read API не заменяют эти пункты. Пользовательские
окна и Safari не используются для управления агентами.

## После отдельного одобрения владельца

1. Зафиксировать точный head, зелёные CI/tests/typecheck/build и текущий release
   pointer. Остановить только собственный local listener перед сменой версии.
2. Сохранить согласованный SQLite backup dispatch.sqlite вместе с WAL-состоянием
   через SQLite backup API, проверить открытие копии и закрытые права. Не копировать
   один живой .sqlite без WAL. Секретный env не выводить и не менять.
3. Сервер обновляется только штатным `bash deploy/deploy.sh` из одобренного commit.
   Скрипт собирает git archive, прогоняет локальный privacy benchmark на сервере,
   переключает release и при неудаче health автоматически возвращает прежний.
4. Проверить exact release pointer, systemd, HTTPS/health, чтение пилотного чата,
   затем отдельно настоящую конечную цепочку и статусы в интерфейсе. Не выдавать
   один health за успешный агентный обмен. Отдельно получить приёмку владельца.
5. Локальный компонент запускается из той же проверенной версии по
   docs/native-desktop-pilot.md, без установки daemon и новых ключей. Его секреты
   и outbox остаются на Mac с закрытыми правами. Старые неопределённые доставки
   не удаляются и не запускаются заново вслепую.

## Откат

Остановить только свой local listener; сохранять его state для сверки поздних
результатов. После отдельного разрешения на откат выполнить из проверенного
checkout:

```sh
bash deploy/rollback.sh 4ee2daf216e2
```

Это точный ранее известный релиз, перед применением проверить, что он по-прежнему
лежит на сервере. Скрипт переключает сохранённый release/service, проверяет health
и возвращает исходный pointer при неудаче. Он не восстанавливает старую базу, не
трогает env, Caddy и другие сайты. Копию базы не накатывать поверх новых состояний
без отдельного согласования: Git-сообщения и очередь могут разойтись.

Сроки вынесены в новую sidecar-таблицу chain_limits, поэтому прежний позиционный
INSERT в chains остаётся совместимым. Task outcome добавлен nullable-колонкой;
старые записи читаются как continue. Истёкшие задания имеют прежний cancelled,
чтобы старый сервер тоже отвергал поздние claims после отката. Старый UI может
не распознать новые причины завершения: после отката автообсуждение не считается
принятым, до сверки оно не включается повторно.

Скрипт отката проверен синтаксически, на production не запускался. Реальное
переключение и восстановление требуют отдельной контролируемой проверки.
