# Замена канала участника — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Владелец чата явно передаёт существующего участника локальному MCP, сохраняя имя, session.id и очередь.

**Architecture:** Владелец в карточке конкретного участника создаёт одноразовое разрешение на 10 минут. Новый локальный MCP предъявляет разрешение, OAuth того же владельца и приватный ключ своего канала; сервер хранит только отпечатки. Замена атомарна, повтор с тем же каналом идемпотентен. Неопределённый взятый ход блокирует замену.

**Tech Stack:** Bun/TypeScript, SQLite, Node MCP stdio, React.

**Spec:** Поручение владельца через мастер-сессию от 04.11.2026; этот документ фиксирует узкий черновой срез.

## Global Constraints

- Черновой PR, без merge, выкладки и изменения живой привязки.
- Никаких сборок, тестовых прогонов и вкладок на Mac; проверки в CI.
- Новый канал — локальный MCP. Перенос ChatGPT cloud в этот срез не входит.
- Никакого отзыва OAuth всего аккаунта, удаления участника, смены alias и ослабления изоляции.
- Разрешения/ключи не попадают в Git, логи, MCP-ответ модели или URL. Одноразовый код показывается только владельцу и передаётся выбранному агенту.

## Review Focus

- Коллаборатор с push, чужой uid, другой чат: не могут разрешить/использовать замену.
- Старый long poll и задержанный take: перепроверка привязки после await, перед claim.
- Взятый, прерванный, отменённый или истёкший неопределённый ход: отказ без повторного исполнения.
- Потерянный ответ замены, повтор, перезапуск: один session.id, тот же приватный ключ, прежняя очередь.
- Stop и готовность: сохраняется owner off; отсутствие подтверждённого канала не превращается в «готов».
