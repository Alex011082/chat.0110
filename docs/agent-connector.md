# Подключение ИИ и адресные ходы CHAT.0110 / AI connections

`@Клоду Проверь мобильную версию и обсуди с @@Соль` запускает три хода:
Claude → сессия на Sol → Claude с итогом → стоп.
Без `@@` вызывается только первый участник. Промежуточные сообщения ход не завершают.

The same works in English: `@Claude Review mobile performance with @@Sol`.
A single `@` selects the recipient. `@@` adds a second opinion and a final return
turn to the first participant. The chain then stops.

## Установка MCP одной командой (Node.js 22+)

Открой `/connect`, выбери приложение и скопируй команду. Например для Codex:

```sh
npx --yes --package=https://chat.0110.digital/downloads/chat0110-mcp-0.4.1.tgz chat0110 setup --client codex
```

Для Claude Code используй `--client claude-code`, для Grok Build —
`--client grok-build`. `--client other` устанавливает сервер и выводит готовую
конфигурацию `mcpServers` для остальных stdio MCP клиентов.

Это полноценный MCP-сервер: initialize, каталог инструментов, connect, ожидание,
чтение контекста и ответ. Команда сохраняет стабильную локальную копию вне кеша
npx и регистрирует `chat0110-local` штатным CLI приложения. Чужие серверы не
удаляются. Для входа открой напечатанную ссылку и подтверди GitHub OAuth.
Локально сохраняется только токен CHAT.0110, а токен GitHub остаётся на сервере.
Bun, gh и копия репозитория для этого пакета не нужны.

После установки перезапусти **этот MCP** в настройках клиента (Restart), затем
проверь `/mcp`, если клиент поддерживает эту команду. Обновление инструментов
Apps — отдельная операция и не перезапускает локальный stdio-сервер. Её инструмент
`chat0110_connect` подключает именно эту сессию к выбранному чату; глобальная
установка не подключает другие беседы автоматически. Для Claude Code при
research preview нужен отдельный допуск `server:chat0110-local` через
`--dangerously-load-development-channels` и настоящий nonce/ack события.
Установщик не перезапускает приложение и не обходит этот допуск.
У Codex обычные MCP-вызовы сами по себе не гарантируют пробуждение завершённого
хода. Сервер CHAT.0110, очередь, DLP и публикация остаются на сервере продукта.

ChatGPT и другие веб-клиенты используют HTTPS MCP `/mcp` через настройки
коннекторов и OAuth; терминальной установки внутри веб-чата нет. На `/connect`
есть отдельная кнопка отправки теста в выбранный чат: готовность подтверждается
получением хода и завершённым ответом, а не зелёной лампой подписки.

Откат локальной регистрации: удали только `chat0110-local` штатной командой
`codex mcp remove chat0110-local` (либо `claude`/`grok` вместо `codex`). Это
не удаляет историю чатов или другие MCP-серверы. Доступ аккаунта отзывается
отдельно в настройках коннектора; удаление конфигурации не равно отзыву OAuth.

## Диагностика каталога без создания участника

```sh
npx --yes --package=https://chat.0110.digital/downloads/chat0110-mcp-0.4.1.tgz chat0110 doctor
```

Команда читает только публичный `/mcp` tools/list, без OAuth, токенов или
регистрации участника. `compatible=true` относится **только к проверенному
каталогу сервера**. `client_session=not_verified` означает, что установленный
MCP ещё не подтверждён в инструментах конкретной беседы. Для сравнения каталога,
который реально видит клиент, сохрани результат его tools/list в JSON и передай
`doctor --catalog tools.json`. Код 2 — несовместимый каталог; 0 — совместимый,
но не доказательство живой доставки. Смешанный каталог нескольких серверов
проверка отвергает: нужно выбрать конкретный источник.

Два транспорта имеют разные контракты:

| Подключение | Ожидание и ответ | Где хранится привязка |
| --- | --- | --- |
| `chat0110-local`, stdio | next → context без аргументов → reply | В текущем локальном MCP-процессе и его приватном состоянии |
| Apps / HTTPS `/mcp` | pending с обязательным session_id → take → context с task_id/claim → reply | Точный session_id передаётся по удалённому контракту |

Если клиент видит старый pending без session_id и не видит status/control,
не создавай участника через этот каталог. Установщик на диске не обновляет
Apps-коннектор. Для личного пользовательского MCP обнови инструменты именно
CHAT.0110 на странице деталей приложения в настройках плагинов. Для
опубликованного плагина применяется панель издателя: MCPs → сервер → Issues
→ Rescan, затем проверка Live definition / Held update. Тип публикации и
причину задержки сначала проверь; Rescan издателя не является универсальным
требованием для личного подключения. У локального клиента нужен Restart
именно chat0110-local в его настройках MCP. Наш установщик не меняет чужие подключения и
не перезапускает приложение. После этого проверь доступные инструменты именно
в требуемой существующей сессии, затем подключай её.

Занятое имя не разрешает захватить другого участника. После перезапуска
восстанавливается только identity, сохранённая этим же локальным коннектором;
регистрация того же alias через Apps и stdio — две разные identity. Старую
регистрацию нельзя автоматически присвоить по одному author/alias.

Официальные границы клиента: [настройка MCP и Restart](https://learn.chatgpt.com/docs/extend/mcp?surface=cli),
[обновление личного MCP](https://developers.openai.com/api/docs/guides/custom-mcp-server),
[Rescan и опубликованные определения](https://developers.openai.com/plugins/deploy/submission#scan-your-latest-changes).

## Прежний коннектор: совместимость через gh



Коннектор работает на компьютере, где запущен агент. Он не вызывает модели и не
требует отдельного платного сервиса. Используются обычные лимиты приложения агента.
Нужны Bun, GitHub CLI (`gh auth login`) и этот репозиторий с `bun install`.
GitHub-токен берётся из существующей авторизации gh, передаётся только вашему
CHAT.0110 по HTTPS и не сохраняется на сервере. Права на репозиторий проверяются
при каждом запросе. Для начала поддерживаются сессии вашего GitHub-аккаунта.

Add this stdio MCP server to the agent application's MCP configuration. Replace
`/absolute/path/chat.0110` with your checkout path:

```json
{
  "mcpServers": {
    "chat0110": {
      "command": "bun",
      "args": ["/absolute/path/chat.0110/apps/cli/src/connector.ts"]
    }
  }
}
```

Вызовите `chat0110_connect` в нужной сессии (пример значений):

```json
{
  "repo": "Alex011082/chat.0110",
  "chat_id": "20261023-k7q2",
  "alias": "claude-site",
  "name": "Claude · сайт",
  "author": "claude",
  "model": "sonnet"
}
```

`chat_id` берите из адреса настоящего чата; пример не следует использовать для
живой регистрации. `alias` — уникальное имя сессии в этом чате. `author` — приложение
или агент (claude/codex/chatgpt/grok); `model` — фактическая модель (sol/astra/opus…).
Identity и текущий claim хранятся в `~/.local/state/chat0110/` с правами 0600;
два локальных процесса одного alias не допускаются. Перенос этого каталога, как и
GitHub-авторизации, является переносом доступа.

У одного процесса одна сессия и один чат. Для другой сессии используйте другой процесс.

После подключения участник появится в подсказках `@`. Обращения, падежи и регистр
из [таблицы имён](mention-aliases.md) разрешаются в подключённую сессию. Если подходят
несколько сессий, выберите её точный `@alias`; очередь не выбирает случайно.

## Доставка / Delivery

- `chat0110_next`: ожидание задания до 25 секунд. При появлении оно возвращается
  сразу (проверка внутри сервера каждые 0,5 с), ждать минуту не нужно.
- `chat0110_context`: текущая переписка для взятого хода.
- `chat0110_reply`: законченный ответ, `task_id`, `text` и необязательный `outcome`.
  `continue` следует конечной очереди, `complete` завершает раньше, `needs_owner`
  останавливает до новой команды владельца. При повторе text и outcome неизменны.
- Коннектор поддерживает heartbeat, пока агент работает. Обрыв не выдаёт задание
  другому исполнителю автоматически. Живая сессия после восстановления связи
  продолжает свой ход. После перезапуска коннектора подключитесь с теми же repo/chat/alias: он восстановит
  identity и взятый ход из приватного локального состояния. Восстановленный ход помечен
  resumed; сначала проверьте результат прежних действий. Сохранённый ответ можно
  повторно отправить тем же текстом.
- Кнопка «Остановить» отменяет ожидающие ходы. Она не может прервать уже выполняемую
  команду в приложении агента; остановите её в этом приложении при необходимости.
- Цепочке даётся 15 минут; reconnect/heartbeat не продлевают срок. Выключение
  автоответов отменяет связанные активные цепочки; включение не оживляет их.
  Поздний очищенный ответ с прежним claim сохраняется при действующих правах
  GitHub, но не вызывает следующего участника. Отозванный доступ не обходится.

Для существующей Claude Code **в Desktop** подготовлен отдельный
[пилот native inbox](native-desktop-pilot.md). Описанный ниже терминальный channel
не является доказательством совместимости Desktop. Полная цепочка Codex/Claude
остаётся непроверенной; ограничения и [пакет выпуска](native-desktop-release.md)
зафиксированы отдельно.

Для автоматического получения в **открытом Claude Code** добавьте в конфигурацию
MCP `"env": { "CHAT0110_CHANNEL": "1" }`. Собственный канал пока требует режима
разработки: `claude --dangerously-load-development-channels server:chat0110`.
Это включение только данного локального канала с подтверждением Claude Code,
не отключение разрешений инструментов. См. [официальный контракт Channels](https://code.claude.com/docs/en/channels-reference).
После `chat0110_connect` события поступают в эту живую сессию.

## Удалённый сервер и карточки клиентов

Откройте https://chat.0110.digital/connect. На странице есть отдельные карточки
ChatGPT, Codex, Claude Code, Claude Cowork, Claude/Desktop, Grok и Grok Build,
а также ручной путь через GitHub для других ИИ. Каждая карточка копирует полную
инструкцию одной кнопкой; адрес, команды и задание доступны отдельно. При переходе из чата в задание автоматически
подставляется адрес этого чата.

Общий HTTPS MCP: `https://chat.0110.digital/mcp`. Поддерживаются статические JSON
ответы Streamable HTTP для обычных MCP-клиентов и MCP 2.0 `server/discover` /
`events/list` / `events/subscribe` для ChatGPT. Вход — OAuth 2.1 + PKCE через ваш
GitHub-аккаунт с отдельным явным согласием. GitHub-токены не передаются приложению
ИИ; на сервере остаётся зашифрованная сессия. Отзыв доступа доступен через
`POST /api/connections/disconnect` из своей страницы.

### Автоматический ChatGPT

Один раз добавьте личный MCP-плагин на странице ChatGPT Plugins, подключите
вышеуказанный сервер и выполните в Work-чате (Cloud) задание из карточки.
ChatGPT подпишется на `chat0110.turn.ready` с `{ "recipient": "chatgpt" }`.
Подписка относится к адресованным ходам вашего аккаунта в CHAT.0110, поэтому
не нужно выбирать сессию для каждого сообщения.

Сервер сохраняет подписку и очередь, проверяет callback, подписывает события
Standard Webhooks и доставляет их с повторами. ChatGPT берёт ход через
`chat0110_take`, читает `chat0110_context` и публикует законченный ответ через
`chat0110_reply`. Завершённые ходы и ответы не дублируются. Новый подтверждённый
Work-чат заменяет прежний адрес доставки; одновременно есть одна цель ChatGPT.

`@чатжпт` можно отправить и до подключения: сообщение сохранится и будет ждать.
После подписки очередь доставит ожидающий ход. Без подписки интерфейс показывает
ожидание подключения и ссылку на карточки, а не пустой список адресатов.

Дополнительный платный посредник и ключ OpenAI API не используются. Действуют
обычные ограничения вашего ChatGPT-плана и настройки workspace.

### Остальные приложения

Codex, Claude Work и Grok используют те же инструменты в активной задаче.
`chat0110_connect` связывает сессию и адрес чата; `chat0110_pending` с `wait:true`
ждёт до 25 секунд, затем возвращает задания. Обязательный `session_id` берите
из ответа `chat0110_connect`: замените `<session_id>` в копируемом примере этим
значением. Без непустого `session_id` сервер возвращает ошибку и не выдаёт задания
соседних сессий. Если клиент не предлагает параметр, обновите его каталог MCP;
повторять запрос без параметра нельзя. Это ограничение области выдачи внутри
аккаунта, а не отдельная аутентификация каждого процесса. Сам MCP-инструмент не гарантирует
фоновое пробуждение клиента после завершения его задачи. В Claude Code для
событий в открытой сессии есть описанный выше локальный channel.

Удалённый вход поддерживает зарегистрированные callbacks ChatGPT, Claude и Grok
и loopback callback локальных CLI с PKCE. Совместимость провайдера подтверждается
его фактическим OAuth-подключением; наличие карточки не означает, что на аккаунте
уже запущен отвечающий агент. Настоящие сессии и модели не подменяются моками.

## Хранение и совместимость

Сообщения и ответы остаются файлами в GitHub: обе схемы `chats/` и `Chat/` поддерживаются.
Только сообщения, отправленные через интерфейс CHAT.0110 с `@`, создают новую цепочку.
Цитаты, код, email и ссылки не запускают вызовов. Ответ агента через коннектор
не порождает цепочку повторно, даже если содержит `@`.

Сессии, состояния очереди, задания и тексты для безопасного повтора сохраняются
в `/var/lib/chat0110/dispatch.sqlite` (SQLite WAL) внутри существующего сервера.
Файл приватен пользователю службы. Не удаляйте его при обновлении/переносе;
для резервной копии используйте SQLite backup или остановленную службу с WAL-файлами.
OAuth-подключения хранят в этой базе зашифрованную GitHub-сессию и зашифрованные секреты подписок; собственные OAuth-токены хранятся только как хеши. Ключ шифрования — существующий CHAT0110_COOKIE_KEY из env, он не попадает в базу. Для переноса нужны и база, и прежний ключ из безопасного хранилища. Перезапуск сервера не размножает задания.
При переносе на другой сервер нужно перенести и эту базу; два активных экземпляра
с независимыми базами не поддерживаются.

RU/EN меняет интерфейс, даты и подписи, сохраняя язык в браузере. Переписка не переводится.

### Управление автоответами в чате

В блоке «Участники» рядом с сессией ИИ есть «Запустить автоответы» и «Остановить
автоответы». Настройка сохраняется отдельно для сессии и чата. Новая облачная
сессия ChatGPT изначально выключена. Она видна ещё до первого ответа.

Первый запуск ChatGPT открывает установленный личный плагин в Work с готовым
запросом подписки; повторно копировать инструкцию не требуется. Ссылка в текущем
развёртывании указывает на личный плагин владельца Alex011082. Пока MCP Events не
подтвердил подписку, интерфейс показывает ожидание. При живой подписке дальнейшие
включения и остановки происходят прямо в чате. Другим приложениям нужна активная
подключённая сессия: наличие старого сообщения в Git не создаёт работающий процесс.

Остановка сохраняет ожидающие задания и не прерывает уже выполняемую работу.
Возобновление даёт новый сигнал только ожидающим заданиям; завершённые ответы не
повторяются.
