# Пилот существующей Claude Code Desktop

Этот компонент доставки не вызывает модель, не создаёт сессии и не устанавливает
службу. Область в коде ограничена YTNG PR522. Codex использует отдельный
host-адаптер: [пилот B2](codex-host-pilot.md) прошёл с тремя настоящими ответами.
Постоянный host/автозапуск после restart не принят.

## Локальная привязка

Приватный JSON вне Git с правами 0600:

```json
{
  "target": {
    "metadata": "<файл метаданных исходной Claude-сессии>",
    "sessionId": "<исходная сессия>",
    "hostSessionId": "<исходная Desktop-сессия>"
  },
  "repo": "Alex011082/Y-TNG",
  "chat_id": "20261030-pp11",
  "alias": "claude-desktop-native",
  "name": "Claude Desktop"
}
```

Не копировать значения из чужих сессий. Метаданные проверяются по identity,
entrypoint, версии и протоколу; inbox должен принадлежать текущему OS-пользователю
и иметь режим 0600. При изменении привязки старый outbox не переиспользуется.
Требуются существующий Bun и уже разрешённый gh login с правами целевого репозитория.
Новых ключей/прав компонент не запрашивает. URL назначения ограничен CHAT.0110
или локальным fixture-стендом: GitHub-токен не отправляется произвольному серверу.

```sh
bun apps/cli/src/native-desktop.ts listen --state <приватная-папка> --binding <приватный-json>
```

Сначала в исходную сессию приходит проба ack. Она должна выполнить только helper
ack с выданными параметрами. При отказе классификатора или отсутствии ack за две
минуты listener завершится до регистрации. Не заменять это отключением разрешений,
другим executor или самостоятельной записью ack-файла. В живой проверке Claude
отклонил именно запуск helper как внешнего кода. 31.10 владелец разрешил его
непосредственно в исходной Claude-сессии; B2 подтвердил самостоятельные
ack/context/reply. Обход отказа запрещён.

После ack listener регистрирует одну сессию и ожидает agent/next. Для каждого
задания в inbox приходит инструкция context → работа → reply. Helper хранит claim
приватно и использует штатный HTTP complete; GitHub-сообщение пишет сервер после
очистки. Проверяются обычные права приложения, переданные ранее владельцем.

## Остановка и восстановление

Остановить только собственный процесс listener через SIGTERM/Ctrl+C. Окна клиентов
не закрываются. Веб-кнопка «Остановить автоответы» отменяет старые цепочки; включение
ждёт нового запроса. На production эти новые правила действуют только после
отдельно одобренного выпуска серверного среза.

Не удалять папку state при неоднозначной доставке: она содержит identity,
fingerprint/счётчики и локальный ответ для восстановления. Сохранённый ответ
повторяется через HTTP с теми же text/outcome, без повторного выполнения модели.
После трёх попыток нужна сверка. При неопределённой inbox-отправке автоматического
повтора нет; надо проверить исходную сессию/PR. Не путать запись bytes в сокет с ack.
Права файлов — 0600, папки — 0700; локальные capabilities/claim в Git и отчёты не идут.

Тест runner работает на временном HTTP/Unix стенде с фиктивным gh и получателем,
а не с живыми моделями. Он подтверждает glue и восстановление потерянного complete,
но не заменяет приёмку двух настоящих Desktop-клиентов. Текущий helper context/reply
работает через приватный локальный mailbox; gh/HTTP остаются у listener, не у модели.
