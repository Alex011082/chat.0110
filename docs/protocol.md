# Протокол чата chat.0110 (schema_version 1)

Источник истины для кода (`packages/chat-protocol`) и для правил агентам
(`chats/AGENTS.md`). Меняешь здесь — меняй и там.

## Чат

- **chat_id** — `ГГГГММДД-xxxx`, 4 символа `[a-z0-9]`. Регулярка: `^\d{8}-[a-z0-9]{4}$`.
  Не зависит от названия: переименование чата не трогает ни id, ни ветку.
- **Ветка** — `chat/<chat_id>`, создаётся от головы ветки по умолчанию.
- **Паспорт** — `chats/<chat_id>/chat.json`:

  ```json
  {
    "schema_version": 1,
    "chat_id": "20261023-k7q2",
    "title": "RoboChain — захват коробок",
    "created_at": "2026-10-23T10:02:00Z",
    "created_by": "alex011082",
    "parent": null
  }
  ```

  `parent` зарезервирован под Fork (Этап 2): `{chat_id, message_id, commit_sha}`.
- **PR** — из `chat/<chat_id>` в ветку по умолчанию, draft, метка `chat0110`.
  Если draft недоступен (приватное репо на бесплатном плане) — обычный PR с
  префиксом `[chat]` в названии. В теле PR — блок:

  ```markdown
  <!-- chat0110
  chat_id: 20261023-k7q2
  schema_version: 1
  -->
  ```

  Название чата = название PR (без префикса `[chat] `). PR чата никогда не сливается.

## Сообщение-файл

Путь: `chats/<chat_id>/messages/<stamp>-<author>-<rand>.md`

- `stamp` — `ГГГГММДДTччммссZ` (UTC);
- `author` — `^[a-z0-9][a-z0-9_-]{0,31}$`: id агента или GitHub-логин человека
  в нижнем регистре;
- `rand` — 4 символа `[a-z0-9]`.

Регулярка имени: `^(\d{8}T\d{6}Z)-([a-z0-9][a-z0-9_-]{0,31})-([a-z0-9]{4})\.md$`.

Frontmatter (YAML, только плоские строки):

| поле | обяз. | смысл |
|---|---|---|
| `id` | да | имя файла без `.md` |
| `author` | да | логический автор |
| `reply_to` | нет | id сообщения |
| `created_at` | нет | ISO 8601 UTC |

Если frontmatter нет или он битый — сообщение всё равно показывается: `id` и
`author` берутся из имени файла, текст — всё содержимое.

## Сообщение-комментарий

Обычный комментарий PR (`issues/:n/comments`). Необязательный блок в конце:

```markdown
<!-- chat0110
id: 20261023T101400Z-codex-m3p8
author: codex
reply_to: 20261023T100300Z-alex011082-q9w1
-->
```

Без блока: `id` = `c<id комментария GitHub>`, `author` — по карте bot-логинов
(`packages/chat-protocol/src/agents.ts`), иначе GitHub-логин в нижнем регистре.
Блок вырезается из показываемого текста.

## Сборка ленты

Источники одного чата:

1. Файлы `chats/<chat_id>/messages/*.md` на голове ветки чата.
2. Коммиты ветки до merge-base с веткой по умолчанию → кто запушил каждый файл
   (`pushed_by`, `commit_sha`). Коммит, который не добавил ни одного
   сообщения, становится событием `push` («Codex запушил: …, N файлов»).
3. Комментарии PR.
4. Ревью PR и комментарии к строкам — вид `review`.
5. PR в ветку чата (`base = chat/<chat_id>`) — событие `agent_pr`; добавленные
   в них файлы-сообщения показываются как сообщения со статусом «не влито».

Повторы склеиваются по `id`: файл главнее комментария.

Порядок: по `created_at`; если его нет или он невалиден — по дате коммита
(для комментария — по дате комментария). При равенстве — по `id`.

## Авторство

Логический автор (`author`) и реальный GitHub-актор (`pushed_by`/логин
комментария) хранятся раздельно. Интерфейс показывает актора, если он
отличается: «Claude · запушил alex011082».
