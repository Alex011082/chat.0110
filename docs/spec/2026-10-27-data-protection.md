# Защита данных CHAT.0110

Согласовано владельцем: автоматически заменять секреты, контакты, реквизиты,
имена и адреса до очереди, GitHub и передачи ИИ. Оригиналы не сохранять.
Область: текст разговоров и их PR; не изображения и не произвольные кодовые PR.

## Реализация

1. Общий серверный сканер: правила для секретов/реквизитов, локальный GLiNER
   для русских и английских имён/адресов. Только очищенный текст и счётчики.
2. Закрыть запись HTTP/MCP/решений/Fork и выдачу старого содержимого. Сбой
   сканера останавливает публикацию. Служебные идентификаторы не изменять.
3. Настройки защиты в чате, предварительная проверка, отметки о заменах RU/EN.
4. Автоматические проверки, локальная модель, измерение на действующем сервере,
   сквозная проверка искусственными данными, независимое ревью.

## Границы

История Git не переписывается. Прямой push обходит CHAT.0110. Распознавание
свободного текста вероятностно. Защита включена всегда; настройки объясняют
категории и позволяют проверить текст, не предлагают небезопасный обход.

На `checkaboutme/20261025-xp8a` воспроизведена долгая первая проверка:

Повторное чтение через публичный API с прогретым кешем — 1,4–1,5 с.

Опрос интерфейса раз в 60 секунд увеличивал номер запроса до завершения
предыдущего: его успешный ответ отбрасывался как устаревший. Несколько
клиентов также могли поставить одинаковый текст в очередь модели до
появления готового кеша. Теперь опросы одной ленты выполняются последовательно,
с одним отложенным обновлением после группы событий; первый ответ сразу
показывается. Одинаковые незавершённые проверки текста объединяются по HMAC.
Ошибки не кешируются, возвращаемые счётчики не разделяют изменяемое состояние.

Защита при чтении сохранена; первая проверка большой старой истории всё ещё
может занимать больше минуты. Интерфейс объясняет ожидание на RU/EN.
Регрессионные проверки покрывают долгий ответ, несколько событий во время
загрузки, независимость разных чатов и повтор после сбоя сканера.

### Постоянный кеш проверенных текстов, 28 октября

Проверенный текст сохраняется в `privacy_checked` существующей SQLite.
Ключ записи — HMAC исходного содержимого; значение — только очищенный текст
и счётчики, зашифрованные AES-256-GCM. Разные ключи для HMAC и шифрования
выводятся из действующего ключа приложения; AAD связывает запись с отпечатком
и версией политики. Исходники и обратные соответствия не сохраняются.

Чтение через HTTP и MCP использует один кеш. Перезапуск процесса, выкатка
интерфейса и вытеснение оперативного кеша не требуют повторного распознавания.
Сохраняется также подтверждение очищенной строки, которую получают следующие
этапы публикации. Placeholder, переданный клиентом, сам по себе ничего не подтверждает.
Изменение текста — новый отпечаток; изменение реализации сканера, worker,
закреплённой модели или словаря обращений — новая версия политики.

Кеш ограничен 64 MiB зашифрованных значений и 20 000 записей; при переполнении
удаляется четверть самых давно использованных результатов. Удаление кеша
влияет только на скорость. Повреждение, неверный ключ или недоступная запись
означают повторную проверку; при недоступной модели неочищенный текст не выдаётся.
Сбой записи кеша не отменяет успешно выполненную проверку.

`bash deploy/check-privacy-cache.sh owner/repo chat-id user-id` прогревает
конкретный чат, проверяет чтение новым экземпляром без работающей модели,
перезапускает приложение и повторяет обе проверки. Выводятся только длительность,
число событий и число вызовов модели; публикаций и вывода оригиналов нет.
