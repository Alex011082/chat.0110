# CHAT.0110 как приложение: Dock и мобильный PWA

Основание: прямое поручение владельца и уточнение «Значок в Dock на Mac».
Docker не требуется. Реализация отдельным коммитом после среза автодоставки;
дизайн Braun и текущая React-архитектура сохраняются. Merge/production отдельно.

## Аудит исходного состояния

Есть responsive-экраны, 100dvh, viewport-fit=cover, safe-area снизу composer,
клеточный SVG-знак, RU/EN и серверный OAuth. Нет manifest, service worker,
установочного UI и app icons. Черновик хранится только в RAM. OAuth next разрешает
connect/authorize, но не deep link чата. Нижняя телефонная навигация перегружена
контролами в одной строке. Размер visualViewport при экранной клавиатуре не учтён.

## Узкий срез

- Manifest со стабильным id, standalone, существующим знаком 192/512 и Apple icon.
- Один небольшой элемент установки в оболочке: реальный beforeinstallprompt, если
  событие доступно; иначе инструкция платформы. Mac Safari — File/Share → Add to
  Dock; iPhone/iPad — Share → Add to Home Screen, Open as Web App. Не утверждать
  «установлено» до настоящего browser event или standalone display mode.
- Авторизация возвращает в тот же допустимый chat/tree URL. Внешние next,
  backslash, control-символы и auth/API-маршруты не принимаются. OS-переход между
  внешним браузером и установленным приложением требует реальной приёмки;
  серверный redirect не доказывает её.
- Service worker кэширует только явно перечисленные публичные offline-ресурсы и
  иконки. API, auth, MCP, запросы с авторизацией, приватные сообщения и токены
  никогда не попадают в Cache Storage. Offline-навигация показывает честный
  публичный экран без переписки и без отправки. В открытом приложении offline
  виден явно, отправка заблокирована, черновик остаётся.
- Обновление применяется по кнопке только после отправки/очистки всех черновиков,
  reply и завершения отправок. Пока есть несохранённый текст — версия остаётся
  прежней, показывается причина. Черновики только в RAM, без новой persistence;
  автоматической отправки после update нет.
- Телефон: две группы навигации, safe areas, visualViewport при клавиатуре и
  textarea 16px без автоматического фокуса/масштабирования. Существующая лента
  и composer остаются главным сценарием, новые постоянные панели не добавляются.

## Приёмка

Контрактные тесты: install/dismiss/standalone, безопасный next и возврат в чат,
allowlist SW без API/auth/MCP, account/logout RAM и отложенное обновление, offline без POST,
обновление без потери draft и reply id. Локальный изолированный headless-прогон:
desktop/телефон, клавиатурная навигация, длинный RU/EN текст, offline-навигация,
переход offline/online, контролируемое обновление. Чужие окна и Safari не трогать.
Реальная установка со значком Dock и на iPhone, системный OAuth возврат и экранная
клавиатура требуют отдельной проверки на устройствах; не объявлять её по тестам.

PWA не даёт отсутствующий Desktop event endpoint и не заменяет приёмку Codex/Claude.
Владелец выбрал только event delivery, модельный heartbeat не добавляется.

## Проверено в реализации

30.10.2026: полный `bun test` — 519 tests / 2060 assertions; typecheck, build,
diff check и механическая проверка Impeccable — без ошибок. Предупреждение
сборки о JS bundle больше 500 kB остаётся.

Изолированный headless Chrome с временным профилем и искусственным API:
desktop 1440×1000, телефон 390×844, уменьшенный viewport 390×470;
реальный SW production-сборки; вызов тестового install prompt с отказом;
обновление двух вкладок без перезагрузки соседнего черновика; выбор reply без
текста, переход в другой чат и обновление; offline send/retry без POST;
offline-навигация и только шесть публичных ресурсов в Cache Storage.
Пользовательские окна и вкладки не участвовали. Снимки desktop/phone просмотрены.

Для повторения проверки обновления: открыть две тестовые вкладки, оставить
черновик во второй, выпустить новую сборку SW, обновить первую по кнопке.
Вторая сохраняет текст и не перезагружается. Её собственное обновление доступно
после отправки/очистки текста и reply. При offline кнопки send/retry недоступны;
новая навигация показывает публичный экран без истории.

Не проверены установкой на реальных устройствах: значок в Dock, iPhone Home
Screen, системный OAuth между браузером/приложением и настоящая экранная
клавиатура. Merge и production не выполнялись.
