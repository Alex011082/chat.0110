# Claude Code: постоянный локальный приёмник существующей сессии

Запрос владельца: довести Claude Code независимо от нерешённого Desktop-host Codex.
Без платных посредников, новых модельных сессий и управления пользовательскими окнами.

## Поведение

- Claude inbox связывается с конкретными sessionId/hostSessionId и приватным файлом
  метаданных. Работает только явно выбранный repo/chat, после самостоятельного ack
  Claude. Названия других открытых сессий не служат разрешением отправки туда.
- Ограничение Claude на прежний единственный пилотный чат снимается. Codex-пилот
  остаётся ограниченным и не получает постоянного запуска.
- `native-desktop.ts start/status/stop` управляет только собственным listener.
  Start сохраняет независимую копию runtime в приватной папке, процесс переживает
  завершение исполнителя. Повторный start не создаёт вторую доставку. Stop
  использует nonce поколения, а не kill произвольного PID. Окно Claude не закрывается.
- Готовность требует ack и рабочего ожидания сервера. Локальный status различает
  starting/waiting/working/reconnecting/stopped/needs_attention. Устаревший status
  не считается живым. Остановка не отменяет уже исполняемую команду в Claude.
- При недоступности сети безопасные запросы восстанавливаются с backoff. Claim,
  текущий job, outbox и сохранённый ответ переживают restart. Неопределённая inbox
  доставка не повторяется. Complete повторяет только прежний ответ с прежними
  лимитами. Секреты и claims не попадают в prompt, stdout или отчёт.

## Минимальный контракт HTTP

`/api/agent/register` дополнительно возвращает
`capabilities.idempotent_next: true`. Старые поля и версия 2.1 сохраняются.
`POST /api/agent/next` принимает необязательный `request_id` (1–100 ASCII букв,
цифр, `_` и `-`). Старые клиенты работают по прежнему контракту.

Новый listener сохраняет request_id до отправки next. Сервер атомарно связывает
его с выданным task в sidecar SQLite. Повтор той же сессии возвращает тот же claim
и task после потери HTTP-ответа и restart. Другая сессия не получает этот claim;
Stop/expiry/done не оживляют ход, прежний request_id не забирает следующее задание.
Без capability новый Claude listener прекращает работу до ожидания заданий:
нужен согласованный выпуск серверной части.

## Приёмка и текущая граница

Локально проверяются HTTP/Unix доставка, start/status/stop отдельного процесса,
восстановление сетевой ошибки и потерянного complete, restart между записью claim
и созданием локального job, защита от дублей и старого stop nonce.

В существующей Claude Code «Чат для ИИ агентов для разработки» получен настоящий
ack: Claude самостоятельно вызвал helper; это подтверждено её tool-use записью.
На действующем сервере capability ещё отсутствует, listener после ack остановился.
Настоящий ответ на новое адресованное сообщение, UI и reconnect после выпуска
ещё не приняты. Протокольный fixture не считается модельной приёмкой.

После согласованного выпуска: старт того же приёмника → ack → включение exact
session в чате → один пользовательский @запрос → самостоятельный context/reply
Claude → один Git-файл и сообщение в UI. Повтор после stop/start своего listener
и временного обрыва; отсутствие повторов. Перезапуск Claude/OS требует заново
проверенной привязки живой сессии, автоматический запуск нового Claude не входит.
