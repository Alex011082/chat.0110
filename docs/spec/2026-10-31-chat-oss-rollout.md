## Интерфейсы, проверки и откат

Расширять существующие понятия: задание/запуск (проект, WORK, инициатор, исполнитель, ограничения, отмена/повтор), доказательство (источник, время, ревизия, артефакт), решение человека (автор, точная версия результата, разрешённое действие), событие (идентичность и продолжение после разрыва). Общая база или библиотека экосистемы не являются скрытой предпосылкой.

До кодового этапа указать реальные владельцы типов/маршрутов в текущем коде и приложить узкий контракт к PR: вход/выход, ошибки, права, миграция/совместимость, откат. Неисследованный механизм сначала заканчивается исследованием, а не выдуманным API. Изменение общего интерфейса согласовать с потребителями до реализации.

Проверки: продуктовая приёмка выше, повтор команды/события, рестарт/переподключение, отмена, устаревшее подтверждение/результат, разграничение доступа, отказ зависимости и лимиты. Выполнить обязательные проверки репозитория по затронутым поверхностям. Старые ошибки сравнить с той же базой; skipped не считать PASS. Начинать на изолированных fixtures; локальный результат, CI, live и приёмку владельцем учитывать отдельно.

Изменения делать совместимыми с существующими потребителями; миграцию и хранение истории определить до изменения данных. Откат не удаляет доказательства/историю: отключить новый адаптер штатным механизмом и проверить старый путь. Выпуск — штатным процессом продукта на точном commit после разрешения; этот документационный PR runtime не меняет.

## Очередь, разрешения и отчётность

Основная очередь: Dev → Mobile → QA → Terminal + Chat → CheckAbout → Творец. Lead / HR / YTNG / Кнессет / Estate — независимые параллельные направления. RoW — последним.

Владелец отдельно разрешил Chat с событийной доставкой и Dock/мобильной PWA сейчас. Остальные последовательные этапы ждут приёмки предшественника или переноса владельцем. Estate ждёт назначенной сессии. Harness² отложен целиком; BHIROT и резервные Aerial/Cognivia/Privacy Policy Generator исключены.

Gateway разрешён только как отключённый offline-контракт. Merge/production, новые расходы, существенная достройка продукта и аппаратные пилоты требуют отдельных решений владельца. HR Discovery остаётся приостановленным. Для Chat допустима только событийная доставка, без проверки очереди моделью каждые пять минут. Ранее выданные разрешения выпуска действуют только на свой точный объём.

После законченного изменения: новый файл в основном PR-чате и запись AI Memory с явным scope своего проекта. Формат: изменения → commit/PR → проверки → доказательства → остаток → нужное решение. Любой отдельный рабочий PR связан из основного чата. Оба канала читать обратно; доставка поручения не равна публикации. PR-чаты не сливаются, история только дополняется.
