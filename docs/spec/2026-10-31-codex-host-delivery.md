# Доставка через существующий Codex host

Основание: владелец поручил закончить доставку в существующую Codex-сессию и
проверить Codex → Claude → итог, без платных сервисов и управления окнами.

Прежний внешний MCP launcher закрывает pipe до tools/list. Его не подменяем
приватным RPC и не создаём другой App Server. Доступный штатный инструмент
`send_message_to_thread` вызывается программным host-адаптером, а не моделью
на каждом тике. Целевая существующая сессия проверяется `read_thread` до старта.

Локальный runner использует прежние register/next/context/complete, приватный
outbox и ack. Для Codex транспорт — JSONL request/receipt через stdio: runner
отдаёт только готовую инструкцию с task identity, host вызывает штатный инструмент
с точным threadId и возвращает квитанцию. Claim не передаётся в транспортный
конверт. Ошибка после начала вызова — uncertain без повторной отправки.

Это адаптер к доступному executor API текущего приложения, а не самостоятельный
публичный Codex endpoint. Без действующего host, его tools и подключения к тому
же приложению runner не готов. Сохранение фонового host после завершения текущего
пилота и после restart приложения отдельно не гарантируется. Пилот ограничен
YTNG PR522 и 15 минутами; его успех не означает production/автозапуск службы.
