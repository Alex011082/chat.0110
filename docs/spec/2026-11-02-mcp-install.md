# Подключение MCP одной командой

Запрос владельца: полностью переделать `/connect`, сократить подключение любого
совместимого агента до минимума, предоставить полноценный MCP-сервер вместо
копируемого задания агенту. Без платных сервисов. Существующие окна и беседы не трогать.

## Сценарий

Выбор приложения → одна команда установки → разовое согласие OAuth. Команда
поставляет исполняемый stdio MCP, а не текст для модели. Node.js 22+ и npx —
явные требования; Bun, gh и checkout пользователю нового пакета не нужны.
Пакет распространяется с нашего HTTPS, публикация в npm не требуется.

Codex, Claude Code и Grok Build регистрируют сервер своими CLI. Установщик
сохраняет стабильную локальную копию пакета, не зависящую от очистки кеша npx.
Повторная установка одинаковой конфигурации безопасна; существующую чужую
конфигурацию нельзя молча удалять. Есть вывод конфигурации для прочих stdio MCP
клиентов. Веб-клиенты ChatGPT, Claude/Cowork и Grok используют существующий
`https://chat.0110.digital/mcp` с OAuth; терминала у этих приложений нет.

Авторизация — OAuth 2.1 PKCE с короткоживущим loopback callback. Токен GitHub
не нужен локальному клиенту. Наш MCP-токен хранится приватно, не выводится
и не входит в команды установки. Отзыв и права доступа действуют на каждом запросе.
Прежний gh-коннектор сохраняет совместимость.
Невалидный MCP-токен не отправляется GitHub как запасной способ авторизации.
Обновление refresh token защищено межпроцессной блокировкой.

## Доставка

Сервер не вызывает платные API моделей, не начинает новую модельную сессию и
не подменяет существующего агента. Установка MCP не доказывает пробуждение ИИ.
MCP initialize не содержит универсального UUID беседы: привязка именно этой
сессии к чату остаётся явным инструментом `chat0110_connect`, а живой канал
подтверждается nonce/ack. Глобальная установка не подключает все MCP-процессы
к одному чату автоматически.
Claude Code требует разрешённого channel; Codex и другие клиенты без такого
канала работают через активные MCP-вызовы. Установщик не обходит этот допуск
и не перезапускает чужой runtime. Состояния интерфейса различают подписку,
ошибку доставки, получение задания и законченный ответ.

На `/connect` — один основной блок установки выбранного приложения вместо
каталога длинных заданий, явный адрес MCP и компактная диагностика выбранного
чата. Русский и английский, клавиатура, узкое окно. Секреты не попадают в URL,
clipboard, stdout MCP, журнал или публичный отчёт.

## Приёмка

- Упакованный файл запускается Node и проходит настоящий MCP initialize/tools/list.
- OAuth PKCE/state, ошибка/таймаут/отзыв, приватные файлы и запросы чужому origin проверены.
- Установка на искусственных CLI/временных каталогах сохраняет остальные настройки;
  повтор не плодит серверы. Нет глобальной установки в настоящий клиент при тестах.
- Реальные MCP-вызовы на локальном API-стенде: connect → next → context → reply;
  повтор ответа, stop и независимые сессии не нарушают очередь.
- HTTP callback 2xx не выдаётся за доказательство ответа ИИ. Нет несуществующих
  обещаний универсального фонового пробуждения.
- tests/typecheck/build, браузер RU/EN и desktop/mobile. Авторизованная живая
  модельная приёмка отмечается отдельно от протокольного теста.
