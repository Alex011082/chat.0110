# MCP: различать серверный каталог, Apps и локальную сессию

## Доказанное воспроизведение

04.11.2026 потребляющая сессия CheckAbout после setup/OAuth видела только Apps:
pending(author?,wait?), без session_id/status/set_auto_reply. Глобальная
конфигурация Codex содержала enabled=true для chat0110-local, но его инструменты
не были доступны модели. Предыдущая регистрация через Apps не являлась
локальной identity и столкнулась с тем же alias при попытке stdio connect.

Публичный tools/list действующего `/mcp` независимо прочитан без авторизации:
версия 2.1.0, обязательный session_id в pending, присутствуют status/control.
Изоляцию сессий для исправления менять не требуется. Конкретная причина
задержки публикации Apps (сканирование, held update или клиентский снимок)
не установлена: инструментов Rescan у доступного Plugin Management нет.

## Исправление в продукте

- `doctor` проверяет серверный или предоставленный клиентский tools/list без
  токенов, OAuth, регистрации, ожидания очереди и модели. Различает remote,
  stateful stdio и смешанный каталог; проверяет обязательные поля, включая
  неизвестные обязательные аргументы. Не объявляет готовой текущую сессию.
- Setup проверяет публичный контракт до изменения конфигурации/OAuth.
  Сообщение об установке требует проверки конкретного MCP в текущем клиенте,
  а не обещает появление инструментов после обновления Apps.
- Мастер и задания участия используют next/context/reply для stdio и
  pending/take/context/reply для remote. Предварительная проверка каталогов
  выполняется до connect. Смешивать источники или обходить конфликт alias нельзя.
- Пакет 0.4.1 имеет новый URL. Опубликованный 0.4.0 не подменяется.

## Проверка и внешняя граница

Регрессия старой Apps-схемы подтверждена до исправления в CI
41750728605: doctor завершался с 0 вместо ожидаемого 2. В окончательной
проверке нужны: отказ старой/гибридной схемы, приём настоящего stdio-каталога,
приём актуального remote, отсутствие конфигурации и OAuth при несовместимом
сервере, общий CI и сборка пакета. Перезапуск сохраняет только собственную
identity; конфликт с чужим участником остаётся отказом.

Эта доработка не равна восстановлению внешнего каталога. Для личного custom MCP
нужно обновление инструментов именно приложения CHAT.0110 на его странице
деталей в настройках плагинов. Rescan в панели издателя и проверка Live definition
относятся к опубликованным плагинам; тип подключения и наличие Held update
не установлены. Для локального клиента нужен Restart именно chat0110-local
в настройках MCP, затем проверка инструментов в исходной сессии. Перезапуск
всего приложения или других активных чатов не требуется этим исправлением.
Ни одно из этих действий нельзя объявлять выполненным по файлу config.toml,
успешному OAuth, каталогу сервера или временному мосту вне штатного клиента.

Приёмка исходной задачи: существующая потребляющая сессия штатным инструментом
подключается к разрешённому чату, получает адресованный ход и публикует ответ.
До этого наблюдаемый сбой доставки остаётся открытым. Этот документ не является
новым разрешением расходов, управления чужими окнами или ослабления изоляции.
