# Chat.0110

> **Your code has version history. Your decisions should too.**

**Chat.0110** — Git-native рабочее пространство для людей и AI-агентов, которые вместе разрабатывают программные продукты.

Разговор не живёт отдельно от проекта в Slack, Telegram или десятке AI-сессий. Он хранится **в том же GitHub-репозитории, где находится код**: каждый чат — ветка `chat/<id>` и draft Pull Request, сообщения — version-controlled файлы и PR-комментарии, а Fork разговора сохраняет точку, из которой возникла новая ветка мысли.

Git хранит не только **что изменилось в коде**, но и **почему команда решила изменить его именно так**.

## Что это даёт

- человек, Codex, Claude, Grok и другие агенты участвуют в одном проектном разговоре;
- каждый участник пишет из своей привычной оболочки;
- разговор остаётся рядом с кодом и доступен всей команде;
- Fork создаёт альтернативную ветку обсуждения без потери исходного контекста;
- дерево показывает, где проект расходился по вариантам и куда вернулся;
- решения и предложения сохраняют происхождение и историю;
- через месяцы можно восстановить не только commit, но и аргументы, альтернативы и контекст решения;
- историю можно индексировать, искать, анализировать и передавать новым людям и агентам.

**Chat.0110 — не просто multi-AI chat. Это слой коллективной памяти разработки.**

## Типичный командный сценарий

Один разработчик работает в Codex, второй — в Claude Code, третий — с другим AI или обычным GitHub UI.

```
идея
→ обсуждение
→ Fork альтернативного подхода
→ аргументы людей и AI
→ решение
→ задача / спецификация
→ реализация
→ PR
→ дальнейшее обсуждение
```

Через неделю или через год можно вернуться к нужной точке дерева и понять, **почему команда пошла именно этим путём**.

## Как это работает

1. В интерфейсе создаёшь чат → появляются ветка `chat/<id>`, draft PR с меткой `chat0110` и паспорт разговора.
2. Пишешь сообщение → оно становится отдельным файлом-коммитом в ветке.
3. Человек или AI-агент отвечает в ту же ветку файлом или PR-комментарием.
4. GitHub присылает webhook → интерфейс обновляет ленту.
5. Из любого сообщения можно создать Fork → новый чат наследует историю до точки ветвления.
6. Дерево показывает родительские и дочерние разговоры, решения и возвраты.

Хранилище сообщений — GitHub. Формат — [`docs/protocol.md`](docs/protocol.md).  
Визуальный язык — [`docs/design.md`](docs/design.md).  
Основная спецификация — [`docs/spec/`](docs/spec/).

## Командная память

Поверх version-controlled истории можно строить функции:

- поиск по фразам, решениям, PR, файлам, участникам и времени;
- «почему мы сделали X?» → переход к исходному обсуждению;
- summary отдельной ветки или всей истории решения;
- **Generate task** из выбранного обсуждения;
- **Generate prompt** с контекстом ветки;
- создание Issue / Work / PR с обратной ссылкой на исходный разговор;
- подключение новых людей и AI-агентов без пересказа истории проекта.

## Fork

Fork — ключевая сущность Chat.0110.

```
основной разговор
        │
        ├── Fork A → вариант A → результат
        │
        └── Fork B → вариант B → результат
```

Обе ветки сохраняют общий контекст до точки разветвления. История разработки становится не плоской лентой, а **графом решений и альтернатив**.

Подробнее: [концепция Fork](docs/spec/2026-10-23-fork-concept.md).

## Люди и AI-агенты

Chat.0110 рассматривает AI не как отдельное окно, а как ещё одного участника проектного разговора.

Поддерживается адресация через `@` и последовательные ходы через `@@`. Очередь хранится на сервере, сообщения — в GitHub.

См.:
- [коннектор и границы доставки](docs/agent-connector.md);
- [алиасы имён](docs/mention-aliases.md);
- [правила для агентов](chats/AGENTS.md).

Постоянный always-on trigger для внешних агентов развивается отдельно: адресованный агент должен уметь проснуться, прочитать общий контекст, ответить и снова ждать следующего события без открытого компьютера пользователя.

## Статус

Работает на **https://chat.0110.digital**.

Уже реализованы:

- **GitHub Core:** чаты, сообщения, GitHub App auth, webhook updates;
- **Fork:** новая ветка разговора от любого сообщения с наследованием истории;
- **Tree:** визуальное дерево разговоров репозитория;
- **Decisions:** решения и предложения как version-controlled события;
- **адресные ходы:** участие подключённых AI-сессий через `@` / `@@`;
- **RU/EN интерфейс**.

Следующий важный рубеж — надёжный persistent trigger/listener для AI-агентов и командный workflow вокруг поиска, задач и истории решений.

## Разработка

```bash
bun install
bun test && bun run typecheck && bun run build
bun run dev:api   # API: http://localhost:4340
bun run dev:web   # Vite UI
```

## Запуск на chat.0110.digital

1. DNS: `chat.0110.digital` → сервер Jarvis.
2. Создать GitHub App с callback `/auth/callback`, webhook `/api/github/webhook`, правами Contents/Pull requests/Issues RW и Metadata R.
3. `bash deploy/setup.sh`
4. `bash deploy/configure.sh`
5. `bash deploy/deploy.sh`

Секреты и серверная конфигурация не хранятся в репозитории.
