# Историческое видео для проверки плагина

Это recording harness, а не сервер приложения и не demo-login. Он обслуживает только собранный web-интерфейс и одну публичную историческую фикстуру через `127.0.0.1`. Все POST/OAuth/MCP и неизвестные запросы запрещены. Фазы меняет только процесс записи. Production-файлы приложения не меняются.

Сценарий воспроизводит PR206 Dream Knesset: Codex удерживает кодовый PR238 до проверки схемы, Claude находит различие Assembly/Plenum, claude-docs исправляет его в fb7eb23. Английские сообщения — явно отмеченные сокращения/переводы исходных цитат из `pr206-sources.json`. Отчёт о 1383 тестах относится к историческому сообщению, эта запись их не запускает. Она также не доказывает автоответы, 5+3 приёмку или выпуск.

Workflow `review-video` запускается на изменении harness в PR или вручную. Он устанавливает Playwright **1.56.1** и его Chromium в отдельный каталог runner, собирает приложение и записывает около 144 секунд. Зависимости продукта и lockfile не меняются. На Mac команды записи запускать нельзя: `record.ts` требует GitHub Actions.

Артефакт: `chat0110-review-video-<head-sha>`. В нём MP4 (H.264, 1440×1080, без аудио), poster, SHA256SUMS, receipt.json и исходный JSON. Receipt различает SHA неизменённого приложения, harness head, checkout CI и исходной истории; содержит размер и хеш каждого медиа, реальную длительность ffprobe, сетевой журнал и границы replay. Сырые WebM не загружаются.

Проверка после скачивания: `sha256sum -c SHA256SUMS`, затем `ffprobe chat0110-pr206-replay.mp4`. Перед передачей модератору надо просмотреть ролик и poster. Сам CI artifact не является публичным video URL; размещение и подачу выполняет уполномоченная сессия отдельно.

Официальная документация: [Playwright video](https://playwright.dev/docs/videos), [network](https://playwright.dev/docs/network). Блокировка service workers нужна, чтобы route-проверка видела все запросы страницы. Внешние ссылки показываются как исторические доказательства, браузер их не открывает.
