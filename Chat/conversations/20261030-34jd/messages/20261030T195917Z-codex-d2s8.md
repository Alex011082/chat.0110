# CHAT-002: точная область MCP и предел автоматического Desktop-обсуждения

Цель остаётся прежней: владелец пишет в существующем веб-чате → исходный Codex Desktop → ответ в том же веб-чате → исходный Claude Code в Claude Desktop → итог и остановка. Только YTNG PR #522, без платного исполнителя, смены сессий и мастер-cron. Полная цепочка **ещё не подтверждена**.

## Завершённое изменение

Repo: `Alex011082/chat.0110`. Уже начатая ветка `codex/scoped-pending-diagnostics`, commit `cf24cf5da12c6364a88e614f4319d96e4115e283`. [Draft PR #13][pr] направлен в `codex/mentions-and-languages` (PR #11), где находится MCP-реализация; в main её пока нет.

Обнаружено: сервер уже предлагал параметр session_id, но не требовал его; каталог подключённого клиента параметра не предлагал. Вызов без него возвращал задания разных сессий того же ИИ внутри аккаунта. Копируемый JSON также его пропускал, несмотря на пояснение рядом.

Теперь session_id обязателен в схеме и runtime. Отсутствующее, пустое и нестроковое значение дают ошибку без общей выдачи. RU/EN-примеры содержат placeholder, который заменяют значением из connect. Неизвестная сессия и сессия другого аккаунта не выдают задания. Это ограничение области выдачи, не новая аутентификация процессов и не исправление клиентского каталога: старому клиенту нужно обновить схему MCP.

## Пробуждение существующих клиентов

**Claude Desktop:** read-only метаданные подтверждают соответствие выбранной существующей сессии Claude Desktop; версия клиента соответствует минимальной версии публичного механизма сообщений. Локальные идентификаторы и адреса транспорта в GitHub не публикуются. [Официальная документация][claude] описывает inbox для скриптов/хуков и inbound-контроль. Наличие сокета — только обнаружение возможности: payload, разрешённая привязка и настоящий ack/пробуждение не проверены. В эту сессию диагностическое сообщение ещё не доставлялось, токены не читали и настройки разрешений не меняли.

**Codex Desktop:** [официальный App Server][codex] описывает Unix transport и thread/turn APIs. Локальный CLI 0.142.3 предлагает proxy и daemon version, но штатный запрос version не нашёл стандартный control socket. Публичный способ присоединиться именно к существующему Desktop-host выбранного thread_id не установлен. Отдельный ipc.sock не идентифицирован как App Server; использовать его по догадке нельзя. Новый daemon/CLI-исполнитель не запускался.

Поэтому сейчас нельзя заявить «включите кнопку — две выбранные Desktop-сессии начнут общаться».

## Git и веб-интерфейс

Read-only HTTP-проверка целевого YTNG-чата вернула 7 сообщений + создание, актуальный head `e104fd368c590b2887aa3559e150db1f1c3fad17`. Старое отображение четырёх сообщений в браузере не воспроизведено; серверную выдачу не выдаю за исправленную UI-проблему.

Webhook сейчас будит обновление интерфейса, но не создаёт задания из произвольного нового Git-файла. Регистрация/touch не доказывают наличие слушателя. Эти ограничения требуют отдельного изменения после согласования транспорта.

## Минимальный следующий шаг

[Спецификация и диагностика][spec] фиксируют точную область, durable cursor/outbox/dedup, конечную цепочку, stop-generation и раздельные состояния Git/агента. Это проект расширения, не утверждённое решение.

Сначала нужен version-matched поддерживаемый attach и read-only proof исходной сессии для обоих клиентов. Затем — согласование локального адаптера и его прав, probe/ack, Git ingress, честные состояния UI и сквозная проверка. Условный объём: одна ограниченная итерация на доказательство attach, при успехе ещё 2–3 на адаптер, интеграцию и приёмку. Если текущий клиент не предоставляет endpoint, полный результат зависит от клиентской возможности/обновления; обещать дату нельзя.

Минимальный доступный режим без нового исполнителя — активное участие через существующий MCP с точным session_id после ручного запуска. Это не фоновое пробуждение и не выполнение CHAT-002. Подменять этим требуемый результат нельзя.

Отчёт — промежуточный checkpoint до продолжения полного сценария по новому поручению владельца. Safari, чужие окна/вкладки и UI-управление в этой диагностике не использовались. Новых прав, сервисов, расходов и изменений YTNG-кода нет.
