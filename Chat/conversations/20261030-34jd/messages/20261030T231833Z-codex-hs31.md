# CHAT-004: ограниченная проверка постоянного Codex host

31.10.2026, Израиль. Проверка после пакетов pl30; продуктовый head остаётся 3124be8616aed09e734fe8b8c88f1932f32037d0. Код, конфигурация клиента, production и окна не менялись. B2 и 532 теста не повторялись.

## Что публично поддерживается

Обнаружена команда codex queue --thread <UUID> --message <text>: она адресует существующую сессию. Это документированный путь, поэтому неверно утверждать, что у Codex вообще нет публичного способа адресной отправки. [Официальная документация](https://learn.chatgpt.com/docs/developer-commands).

Bundled CLI приложения: 0.166.0-alpha.5.1, queue присутствует в --help. Homebrew CLI: 0.142.3, в его списке команд queue отсутствует. Проверены только --version/--help и read-only daemon version, модели не запускались.

Для постоянной реализации нужен работающий поддерживаемый shared host: listener сохраняет привязку к прежнему UUID, а пришедшее событие вызывает queue и проверяет самостоятельный ack. App-server документирует thread/read, thread/resume и Unix transport; это не разрешение подключаться к частному IPC приложения. [Протокол](https://learn.chatgpt.com/docs/app-server).

## Результат доступности на этом Mac

Bundled codex app-server daemon version завершился ошибкой ENOENT для стандартного публичного control endpoint. Отдельный lstat подтвердил, что стандартный endpoint отсутствует. Это не ошибка авторизации и не доказательство отсутствия всех возможных custom endpoints: другой публичный адрес существующего desktop host не предоставлен и текущим tool-каталогом не объявлен.

queue --help сообщает: --resume пытается возобновить thread, но при неуспехе выдаёт warning, а сама команда всё равно может завершиться успешно. Поэтому exit 0 нельзя считать доказательством запуска модели. Сам queue не вызывался: при отсутствии проверенного host это могло бы лишь записать сообщение или автоматически создать daemon, что не соответствует нынешнему scope.

daemon bootstrap --help подтверждает возможность durable management. bootstrap/start/restart, remote-control/pair, новые server/process/session и миграция текущей сессии не выполнялись. К пользовательским/частным sockets не подключались.

## Почему имеющийся ZIP не решает restart

MCP Events документирован для Work web, Work desktop с Cloud и dots. Документация предусматривает серверное сохранение/refresh подписок, но не устанавливает такую capability для локальной Codex-сессии. [MCP Events](https://developers.openai.com/plugins/build/mcp-events).

У hooks другая граница: завершение async hook при простаивающем чате не запускает новый ход; после завершения сессии незаконченные hooks отменяются. Следовательно, hook не превращает существующий remote MCP пакет в постоянный адресный receiver. [Hooks](https://learn.chatgpt.com/docs/hooks).

В текущем каталоге codex-app-tools есть разовая send_message_to_thread и расписания, но нет операции установки durable event callback/host. functions.exec держит инструменты только в своём активном executor; фоновое обещание не сохраняет этот доступ после его окончания. Расписания с модельным опросом, master relay и private IPC исключены.

## Конкретный внешний блокер и одно решение владельца

Недостаёт доступного публичного shared-host endpoint для текущей существующей сессии и разрешения обеспечить его постоянную жизнь. Это блокер установленной конфигурации и текущего ограничения «без нового App Server», а не доказанный запрет платформы вообще.

Одно решение, позволяющее продолжить: разрешить управляемый официальный shared app-server и перевод на него этой же сохранённой Codex-сессии с проверкой прежнего UUID, без новой беседы, модели, API-ключей или платного сервиса. Это явное изменение прежнего запрета, а не действие установки ZIP. После разрешения сначала проверяются exact UUID/context/permissions и ack через публичный queue, затем разрыв host-соединения и восстановление. До этой проверки миграция, гарантия restart и самостоятельные автоответы не считаются выполненными.

Если запрет сохраняется, доступный сейчас подтверждённый вариант остаётся ограниченным живым executor B2; обещать постоянную локальную доставку нельзя. Перезапуск пользовательского приложения ради эксперимента не выполнялся.
