## Что входит

- Новая RU/EN страница /connect: выбор приложения, одна команда установки настоящего stdio MCP для терминальных клиентов; HTTPS MCP и OAuth для веб-клиентов. Установка требует Node.js 22+/npx, без checkout, Bun, gh и платного посредника.
- Собственный пакет 0.4.0 с нашего HTTPS, стабильная локальная копия, регистрация отдельного сервера chat0110-local штатными CLI Codex/Claude Code/Grok Build; стандартная mcpServers-конфигурация для других совместимых клиентов. Чужие записи не удаляются.
- OAuth PKCE/state/issuer, приватное хранение токенов и блокировка одновременного refresh. GitHub-токен остаётся на сервере; невалидный MCP-токен не уходит в GitHub через fallback.
- Диагностика выбранной сессии, явная отправка тестового адресованного сообщения и повтор с тем же request_id. Ошибка callback, активная подписка, получение задания и завершённый ответ различаются.

Спека: [docs/spec/2026-11-02-mcp-install.md](https://github.com/Alex011082/chat.0110/blob/f5a853e9670c9d4c5b2eaba75877b8aa54df397a/docs/spec/2026-11-02-mcp-install.md).

## Доставка и оставшаяся граница

При диагностике показанного чата адресованных заданий не найдено; одиночный @ не запускает участника. Активная подписка либо принятый HTTP callback подтверждают маршрут события, но не чтение и ответ модели.

PR19 — промежуточный срез установки и диагностики. Для событийного пробуждения существующего Codex после завершения его активного хода нужен проверенный адаптер хоста: точная сессия и поколение, разрешение на доставку, защита от дублей, восстановление после перезапуска, подтверждённый возврат ответа. Для Claude нужен допущенный живой channel/адаптер соответствующего приложения. Установка MCP сама по себе этого не доказывает. Полный реальный обмен Codex → Claude → итог в чате здесь не закрыт; циклический опрос заменой этому не предлагается.

## Готовые шаги выпуска и отката

После явного разрешения владельца на PR19: повторно сверить head и CI; merge с expected_head_sha; получить точный merge-коммит и проверить дерево; из чистого состояния выполнить штатный deploy/deploy.sh. Затем проверить health, активный релиз, публичные JS/CSS, загрузку .tgz и SHA256, Node/npx handshake. Отдельно, с конкретным допуском на настройки клиента и OAuth, проверить настоящую установку, адресованный ответ и восстановление доставки; окна владельца не трогать.

Штатный deploy/deploy.sh проверяет защиту данных до переключения и возвращает предыдущий релиз при неуспехе health. Для явного отката предусмотрен deploy/rollback.sh с точным SHA сохранённого релиза; предыдущую версию надо сверить перед выпуском. База и секреты сохраняются. Локальную регистрацию можно удалить штатным CLI только по имени chat0110-local, не затрагивая другие MCP. Откат сервера не удаляет уже установленный пакет и не отменяет пользовательское OAuth-согласие автоматически.

Плагины остаются кандидатами для проверки: официальный статус и отправку на модерацию не заявляю.
